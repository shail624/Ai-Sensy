# PAR-DL-01 — Unified Download Center

**Status:** Repository Implemented  
**Date:** 2026-08-24  
**Scope:** Give each entitled operator one secure history for existing contact and analytics exports

## Decision

The existing `exports` record, queue, storage artifact and signed-URL pipeline remain the sole
authority. A new `GET /api/v1/downloads` projection and `/downloads` workspace surface expose that
authority without adding a second job table, artifact store, queue or retry path.

## Security boundary

Every result is constrained by organization, requesting user and current permission. Contact
exports require `contacts:export`; analytics reports require `analytics:export`. Holding either
permission makes the route visible, but never reveals the other family. Jobs requested by another
user remain invisible even inside the same organization.

Ready artifacts receive fresh short-lived signed links. A ready row whose artifact retention has
elapsed is projected as `expired` and never receives a link. Pending, processing, ready, failed and
expired status filters use the same normalized semantics.

## Product experience

Download Center is an entitled Tools tab with type/status filters, server-owned newest-first keyset
pagination, row counts, creation and expiry timestamps, explicit queued/preparing/failed/expired
states, manual refresh and automatic three-second polling while the visible page contains active
work. Filter state is URL-backed and the route has complete loading, error, empty and permission
boundaries.

## Scope boundary

This slice covers every artifact already generated by the shared export pipeline: contact exports
and analytics reports in CSV, Excel or JSON. It does not invent PDF generation, Chat History
transcripts, campaign/scan exports, generated documents, report schedules or new artifact retry
authority. Those source capabilities must be implemented before their artifacts can appear here.

No database migration, new permission code, queue, storage provider or customer-facing send is
added. Migration head remains `0048_automation_wait_subscriptions` (**49 revisions**). OpenAPI
advances **211 → 212 paths** and the generated TypeScript client is synchronized.
